# Localization

Status: structure ready, two locales (`en`, `id`), language toggle in the navbar, no URL routing.

## Layout

| Path | Holds |
| --- | --- |
| `messages/en.json`, `messages/id.json` | Every user-facing string: headings, labels, aria-labels, paragraphs, CV/work/project copy |
| `config/site.ts` | Everything that is not language: images, URLs, company names, tech names, nav hrefs, date ranges (`start`/`end`) |
| `i18n/config.ts` | `locales`, `defaultLocale`, `LOCALE_STORAGE_KEY` |
| `i18n/dictionaries.ts` | Locale → dictionary registry, `Dictionary` type |
| `i18n/format.ts` | ICU formatting via `intl-messageformat` (already a dependency) |
| `i18n/context.tsx` | `LocaleProvider`, `useT()`, `useFormat()`, `useLocale()` |

`app/layout.tsx` wraps the app in `<LocaleProvider>` and renders `<html lang={defaultLocale}>`. The provider syncs `document.documentElement.lang` and persists the chosen locale under `portofolio-locale`. On first visit (no stored choice) it falls back to the first `navigator.languages` entry that is a supported locale.

## The toggle

`components/language-switch.tsx` (rendered by `components/navbar.tsx`, desktop and mobile) calls `setLocale` from `useLocale()`. It renders one button per entry in `locales`, so a new locale shows up automatically after steps 1–3 below; `SHORT_LABELS` / `LANGUAGE_NAMES` are the only per-locale constants.

## Reading strings

```tsx
const t = useT();                 // typed dictionary, no key strings to typo
const format = useFormat();       // ICU message → string

{t.nav.home}
{format(t.projects.emptyState, { filter: t.projects.filters[filter] })}
{format(t.common.photoCount, { count })}   // {count, plural, one {# photo} other {# photos}}
```

`app/layout.tsx` is a server component and formats metadata with `formatMessage(defaultLocale, …)` directly.

## Data vs. copy

`config/site.ts` entries carry an `id` (`padepokan`, `civiku`, `tedc`, …) and the dictionary holds the copy under the same id:

```ts
siteConfig.work[0]        → { id: "padepokan", company, image, roles: [{ id, start, end }], gallery: [...] }
t.experience.work.padepokan → { location, story, roles: { "software-developer": {...} }, gallery: { "team-moment": {...} } }
```

The `defineWork` / `defineProject` / `defineEducation` helpers in `config/site.ts` type `id` as a literal, so a typo or a missing dictionary branch is a build error rather than `undefined` on the page.

Two casts remain in `app/experience/page.tsx` (`work.roles`, `work.gallery`): TypeScript cannot correlate a union-typed work item with its own dictionary branch.

## Adding a locale (e.g. `id`)

1. Copy `messages/en.json` to `messages/id.json` and translate the values. Keys, array lengths, and nested ids must stay identical — an array of 4 `jobDesc` entries stays 4 in every locale.
2. `i18n/config.ts`: `export const locales = ["en", "id"] as const;`
3. `i18n/dictionaries.ts`: `import id from "@/messages/id.json";` and add `id` to the `dictionaries` record. Type errors then point at every key that is missing in the new file.
4. `components/language-switch.tsx`: add the short label and language name for the new locale.
5. For SEO, `metadata` and `html lang` still come from `defaultLocale` — they need per-locale handling (plus `hreflang`) once URL routing (`/id`) is decided.

Placeholders must stay identical across locales (`{years}`, `{count, plural, …}`); Indonesian keeps both `one` and `other` plural branches so the ICU message parses for either locale.

## Deliberately left in `config/site.ts`

- Tech names, company names, school name, social handles: proper nouns.
- `skill[].details` / `skill[].highlights`: library and architecture terms (`BLoC / Cubit`, `Clean Architecture`).

## Open items for a real switcher

- `date` / `duration` strings (`"September 2023 - Present"`, `"3 Months"`) are literal copy, not `Intl.DateTimeFormat` output. Only the computed duration for ongoing roles goes through ICU plurals.
- The chat widget replies from `api.nurdinahmadalawiyah.web.id/api/chat`; the request body has no `locale` field yet, so answers would stay English after a switch.
- Changing locale resets the chat conversation.
